# Formloom

A CPU-first, non-neural procedural still-life generator. Images are constructed from geometry, gradients, authored scene rules and seeded detail—not models, stock images or downloaded textures.

## Current slice

The desktop UI now connects the Core scene generator to the Skia CPU renderer:

- Prompt, editable unsigned 64-bit seed (default `42`), Randomize, variation slider (default 35%), Generate, preview and Save PNG.
- Supported prompts: `a red apple on a wooden table`, with `green` or `yellow` in place of `red`. Parsing tolerates case, whitespace and terminal punctuation; unsupported text is rejected explicitly.
- Generation runs off the UI thread. Duplicate actions are guarded; failed prompts retain the previous image. Preview metadata and save filenames describe the last successful generation, even if the controls are subsequently edited.
- Save PNG opens PhotinoX's asynchronous native save dialog and writes the generated bytes, not a screenshot. Cancellation retains the image. Default filename: `formloom-apple-seed-42.png`. Filenames must end in `.png`; save errors are reported without stack traces, and technical details are logged.
- Default output is 1024 × 1024. Core supports dimensions of 64–4096 and finite variation in 0–1. Geometry uses normalized coordinates; higher variation scales bounded offsets, rather than changing the subject.

The integrated UI passed Linux Release CI in PR #7, and the user confirmed that the app works on Windows. Detailed visual review, repeat-click determinism, seed/variation comparisons, unsupported-input handling, save cancellation/failure, independent PNG viewing and close/relaunch remain individually unverified. The initial milestone is at its verification/review checkpoint, not yet fully signed off.

## Layout

- `Formloom.Core`: immutable scene types, validation, prompt parsing, PCG32, stable UTF-8 FNV-1a named random streams and scene construction. No rendering or UI dependency.
- `Formloom.Rendering.Skia`: disposable CPU raster resources, procedural setting/apple/stem/leaf, shading and PNG encoding. Returns dimensions and PNG bytes.
- `Formloom.Desktop`: PhotinoX.Blazor executable, UI, generation orchestration and native PNG save service.
- `Formloom.Tests`: Core and renderer tests, including PCG reference values, independent streams, PNG decoding/sizes, rendered-pixel repeatability and seed differences. Does not reference or launch Desktop.
- `Formloom.slnx`, `Directory.Build.props`, `Directory.Packages.props`, `.editorconfig`, `global.json`: solution and shared configuration.
- [`.agents/todo.md`](.agents/todo.md): implementation plan and outstanding acceptance criteria.

## Prerequisites and commands

Use the latest installed **.NET 10 SDK** servicing release (C# 14); a runtime alone is insufficient. Restore needs NuGet connectivity. The Windows desktop host requires **Microsoft Edge WebView2 Runtime**.

From the repository root:

```sh
dotnet restore Formloom.slnx
dotnet build Formloom.slnx --configuration Debug --no-restore
dotnet build Formloom.slnx --configuration Release --no-restore
dotnet test --solution Formloom.slnx --configuration Release --no-build --report-trx --results-directory TestResults
dotnet run --project Formloom.Desktop/Formloom.Desktop.csproj --configuration Release
```

The native window is titled **Formloom** and starts at 1400 × 900. Startup uses the upstream PhotinoX.Blazor 5.3.5 API with an STA entry point and explicit application disposal. The package exposes the `Photino.Blazor` namespace but is **PhotinoX.Blazor**, not the original package. Static content is copied for build/publish and resolved from the executable directory.

## Windows acceptance check

1. Launch, check styling and keyboard focus, then generate the default prompt with seed 42 and 35% variation. Verify a recognizable apple, table grain, coherent lighting and contact/cast shadows.
2. Generate the same values again; verify the same image. Randomize the seed, then generate; verify a coherent difference. Compare low/high variation and red/green/yellow prompts.
3. Enter an unsupported prompt or invalid seed; verify an actionable error and that the last image remains visible.
4. After successful generation, edit the controls without generating. Save PNG; confirm the filename still uses the displayed image's seed, not the ungenerated controls.
5. Exercise Save cancellation and a save failure. Save successfully, then open the PNG in an independent viewer and verify 1024 × 1024 dimensions.
6. Resize the window, close it and relaunch; check for UI/startup/shutdown errors.

## Dependencies and CI

Versions are centrally managed; no selected stack dependency was substituted:

| Package | Version | Purpose |
| --- | --- | --- |
| PhotinoX.Blazor | 5.3.5 | Native Blazor host and asynchronous save dialog |
| SkiaSharp | 4.154.0 | CPU raster rendering |
| SkiaSharp.NativeAssets.Linux.NoDependencies | 4.154.0 | Linux renderer native assets |
| xunit.v3 | 4.0.2 | Tests |
| Microsoft.Testing.Extensions.TrxReport | 2.5.1 | Native test-runner TRX reports |
| NewStyleCop.Analyzers | 1.2.1 | Repository analyzer |

`global.json` selects Microsoft.Testing.Platform; use `--solution` and `--report-trx`, not VSTest's positional solution and `--logger` syntax.

[CI](.github/workflows/ci.yml) runs one Ubuntu **Linux / Release** job for PRs, main pushes and manual dispatch: restore, build with warnings as errors and test. NuGet packages are cached; test results and a **procedural-preview** artifact are uploaded. The latter contains `formloom-apple-seed-42.png` from the default export test, also available locally beside the test assembly under `artifacts/bin/Formloom.Tests/`.

Core, renderer, desktop host and integrated generation/save UI passed Linux Release CI in PRs #4–#7. CI does not verify native Windows/WebView2 behavior. Require **Linux / Release** in `main` branch protection to enforce it; obsolete Windows check requirements should be removed.

The agent sandbox is Debian 12 without a .NET SDK; per user direction, SDK-based validation is delegated to CI. GitHub's redirected artifact storage is inaccessible from this sandbox, so the generated PNG has not been visually inspected here. Download `procedural-preview` from Actions or inspect the generated preview in the Windows app. Do not mark visual acceptance complete based only on tests.

## Current visual-polish pass

Review of the user-provided seed-42 PNG confirmed a recognizable opaque apple, but identified weak grounding and a flat stem socket. The current renderer changes soften the broad cast shadow, add localized elliptical contact shadows beneath both lower lobes, replace the flat socket oval with a clipped, fading indentation, and draw a tapered, shaded stem with a subtle bark ridge. Wood grain, apple highlight, scene inputs and named random streams are unchanged. Contact-shadow tests are added; execution and before/after visual approval remain pending. Existing outputs will change with this renderer build while same-build repeatability is preserved.
